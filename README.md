# Relay — живий конвеєр агентів

Гейміфікована візуалізація мультиагентного пайплайну: 8 агентів по черзі беруться
за роботу і передають «пакунок» один одному, а глядач бачить це в реальному часі —
з подіями, статусами, рівнями та лічильником передач.

Два режими:

- **демо**: піксельне інтернет-кафе на змодельованому прогоні. Кубик 🎲 перемішує
  столи й бере випадковий склад агентів.
- **наживо**: твої справжні сесії Claude Code. Головний Claude сидить за своїм столом;
  коли він запускає субагента, то встає й несе йому задачу, субагент працює (над
  головою хмарка з поточною дією), а потім приносить результат назад.

## Наживо: підключити свій Claude Code

Два способи, і обидва — одна фраза для свого Claude Code.

### Хмарно, через сайт (для всіх)

На https://agent-pipeline-viz-one.vercel.app/connect сайт видає особистий ключ і готову фразу з хуками. Claude
дописує їх у `~/.claude/settings.json`, і далі агенти видно на сайті, з будь-якого пристрою (посилання
`/#k=<ключ>`). Фраза кладе короткий скрипт хуків у `~/.config/relay/relay.sh` (сайт віддає його як `/relay.sh`, а
фраза звіряє sha256) і, якщо можна, додає статус-рядок для лімітів.

```
Claude Code hooks ──curl──▶ Vercel /api/claude-hook?k=<ключ> ──▶ normalize ──▶ Supabase rpc relay_ingest
                                                                                  │ realtime.send(relay:<sha256(ключ)>)
сторінка: rpc relay_snapshot (знімок) + Realtime broadcast ◀───────────────────────┘
```

- Supabase-проєкт `relay` (`tebhpitpwijkrxthxpcy`, Франкфурт) в окремій організації `Relay` (`wetxsehqqnjowburqbvf`).
  З safeapp/Guard не ділить нічого: ні організації, ні білінгу, ні ключів. Схема в `supabase/migrations/0003_live_rooms.sql`.
- Таблиця закрита RLS, ходять лише дві функції за ключем. Кімната — це `sha256(ключ)`, сам ключ ніде не лежить.
- Події живуть добу (pg_cron) і не більше 5000 на кімнату.
- На сервер іде лише нормалізоване: короткі описи дій, імена агентів, назва папки. Вміст файлів і повні тексти
  відкидаються одразу у `lib/live/normalize.ts`.
- Хуки на `UserPromptSubmit` і `SessionStart` додають список файлів з `.claude/agents`, тож за столи сідає вся
  команда, навіть хто ще не працював.
- Змінні для Vercel: `NEXT_PUBLIC_SUPABASE_URL` і `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` (див. `.env.example`).

#### «Потрібна твоя увага»

Коли Claude просить дозвіл (`Notification`) або закінчив хід (`Stop`), чат отримує стан, який видно звідусіль:

- на вкладці чату жовтий «! чекає» або зелений «✓ відповів», у заголовку сторінки `(N)`;
- у кафе агент піднімає руку, на моніторі блимає «!», над столом жовта табличка з тим, чого він чекає;
- кнопка «сповіщення»: звук (поки сторінка відкрита) і веб-пуш на телефон чи комп'ютер, навіть із закритим сайтом.
  На iPhone пуш працює лише з іконки на початковому екрані (маніфест `app/manifest.ts`, воркер `public/sw.js`).

Пуш іде з того самого хука: `/api/claude-hook` відповідає 204 одразу, а через `after()` бере пристрої кімнати
(`relay_push_targets`) і шле їм `web-push`. Хто хоче лише дозволи, отримує їх одразу, а «Claude відповів» через
хвилину тиші, коли Claude Code сам шле нагадування. Хто ввімкнув «одразу, щойно відповів», отримує `Stop` без
затримки. Пристрої, які зникли (404/410), вимикаються прапорцем `active`. Схема `supabase/migrations/0004_push_subs.sql`.
Кнопка «поділитися» в шапці записує 15-секундний кліп кафе (`components/cafe/clip.ts`: `captureStream` +
`MediaRecorder`; підписи, бульбашки й вивіска перемальовуються в кадр у `overlay2d.ts`, бо на сайті вони DOM) і
дає посилання лише для перегляду `/#v=<sha256(ключ)>`. Воно читає ту саму кімнату через `relay_snapshot_room`
(`supabase/migrations/0005_view_links.sql`), але без ключа: писати в кімнату чи вмикати пуші глядач не може.
Закрити доступ можна лише новим ключем.

«Підсумок» на «наживо» показує день і тиждень: питання, дії, доручення, активні хвилини, чати, серію днів, топ
агентів, інструментів і проєктів. Цифри лежать у погодинних лічильниках `relay_hourly`: їх веде тригер на
`relay_events` (`supabase/migrations/0006_hourly_recap.sql`), який ловить будь-яку свою помилку, тож запис подій
зламати не може. Лічильники переживають добове прибирання подій. Локальний Relay рахує те саме з пам'яті
(`lib/live/recap.ts`). Звідти ж «програти цей чат у 10×» (паузи стиснуті до 15 с) і картка дня 1080×1350 PNG.

«Кафе росте»: 18 досягнень за весь час (`lib/live/achievements.ts`), рахуються з тих самих погодинних лічильників,
розкладених по локальних днях (`relay_progress`, `supabase/migrations/0007_cafe_progress.sql`). Дев'ять із них
ставлять у кафе річ: гірлянду, сову на підвіконні, кубок на автоматі, вогнегасник, аркадний автомат, акваріум,
золоту кавоварку, рослину в кутку й корону коту (`components/cafe/decor.ts`). Нове досягнення показується плашкою
один раз на браузер (`relay.seenAch`); ті, що вже були до першого відкриття, записуються мовчки. Ім'я кота
зберігається в `relay_rooms` через `relay_room_set` (лише з ключем, до 24 символів), тож його видно й за
посиланням для перегляду. Локально ім'я лежить у `localStorage`, а прогрес рахується з подій у пам'яті.

«Командне кафе»: кілька людей підключають своїх Claude до одного ключа, і кожен хук несе ім'я учасника
(`/api/claude-hook?k=<ключ>&m=<ім'я>`, `lib/live/member.ts` чистить його до 24 символів). Коли в кімнаті
з'являється більше одного автора, сторінка ділить її за людьми (`lib/live/team.ts`): у будинку кожен має свій
поверх, а в лобі внизу «уся команда», де за столами сидять самі учасники (`lib/live/teamModel.ts`; хто мовчить
5 хвилин посеред ходу, засинає). У залі над сценою лишається смужка учасників, щоб перейти до чужого чату. Запрошення `/connect#team=<ключ>` дає повний доступ до кафе, тож лише для своїх.
Звук, заголовок і пуші стосуються тільки твого Claude: пристрій запам'ятовує учасника
(`relay_push_subs.member`, `supabase/migrations/0008_team_push.sql`), і чужі запити дозволу його не будять.
Браузер пам'ятає всі відкриті кафе, тож особисте не губиться, коли приєднуєшся до команди.

Будинок (`components/live/House.tsx`, `lib/live/house.ts`). Замість рядка вкладок кафе показано будинком у розрізі:
кожен чат за останні 6 годин є окремою залою, і всі зали живі одночасно (`components/cafe/MiniCafe.tsx` малює ту саму
сцену дрібно, вісім разів на секунду, без імен і бульбашок). Соло-кафе ставить по три зали на поверх, найсвіжіші
внизу; командне дає поверх кожній людині, твій найнижче. Зала, де Claude чекає на тебе, світиться «! чекає». Клік
наближає залу до повної сцени (View Transitions, а де їх немає, просто перемикає), кнопка з будиночком у шапці
віддаляє назад. Будинок з'являється, коли чатів хоча б два або в кафе є команда; вибір «будинок чи зала» браузер
пам'ятає, а пуш завжди відкриває свою залу.

Зали підписані так само, як чати в Claude Code («Баг пайплайн», «Jira ticket SCRUM-30»), а не іменем папки.
Claude Code щоходу дописує назву чату в транскрипт (`"customTitle"`), і хуки на початку сесії, питанні, відповіді та
сповіщенні беруть її з останнього мегабайта транскрипту й шлють після рядка `#relay-title`
(`lib/live/hookConfig.mjs`, `plugin/scripts/relay.sh`). Без назви зала лишається з іменем папки. Щоб назви з'явились,
хуки треба оновити: ще раз віддати Claude фразу зі сторінки підключення, `npm run hooks` локально або оновити плагін.

Кафе живе за годинником того, хто дивиться (`components/cafe/daylight.ts`): світанок з 5:30, день з 8:00, вечір з
18:30, ніч з 22:00. Вдень у вікнах блакитне небо з сонцем і в залі світліше, на світанку й увечері низьке червоне
сонце, уночі місяць і зорі. Коли вночі ніхто не працює і Claude тебе не чекає, кафе зачиняється: неон гасне й пише
«зачинено до ранку», на дверях табличка, бариста йде додому, агенти дрімають. Агенти без роботи щось роблять
(`components/cafe/idle.ts`): за 15 секунд після готового читають книжку, грають у карти чи дрімають, кожні 40 секунд
щось інше. Передача задачі тепер видна через усю залу: паперовий літачок злітає зі столу того, хто доручає, летить із
хвостом і тінню на підлозі й падає зі спалахом на стіл того, хто отримав (`components/cafe/flight.ts`). Кнопка з
динаміком у верхній панелі вмикає музику кафе (`lib/live/lofi.ts`): lo-fi на чотирьох акордах, яку браузер складає на
льоту, без жодного файлу. Чим більше агентів працює (у будинку: скільки зал активні), тим гучніше музика й тим частіше
клацають клавіатури; коли не працює ніхто, клавіатури замовкають. Повзунок поруч задає гучність. Музика вимкнена, поки
її не ввімкнеш, і браузер пам'ятає і вибір, і гучність.

Перерви (`components/cafe/outing.ts`, `outingSprites.ts`). Агент, що відпочив після роботи, на початку кожного
двохвилинного слоту з імовірністю 1/2 встає з-за столу: іде до бару по каву, до автомата по банку, сідає на диван
(двоє на одному дивані балакають), грає на аркаді чи ставить платівку на джукбоксі, потім вертається й п'є за столом.
Місця роздаються на слот, тож двоє не стають в одне. Усе виводиться з годинника й стінтів, тому всі глядачі бачать те
саме. Питання від Claude («! чекає») одразу повертає агента за стіл, а «✓ відповів» ні. Уночі, коли кафе зачинене,
ніхто не виходить. Коти час від часу сплять на поставленій лежанці, по одному.

Бар і чат (`components/cafe/guests.ts`, `lib/live/useChat.ts`, `components/live/ChatPanel.tsx`). Біля бару шість
місць: три стільці біля стійки й три біля високого столика перед нею. Сідають усі, хто відкрив кафе, і ти теж
(підписаний «ти»), у тому самому порядку на кожному екрані; кому не вистачило місця, той «+N». Клік по бару або кнопка
з бульбашкою в шапці відкриває груповий чат кафе. Повідомлення лежать у `relay_chat` під кімнатою
(`supabase/migrations/0012_chat.sql`): пишуть ті, в кого є ключ, читають також за посиланням для перегляду, не частіше
20 повідомлень на хвилину на кафе. Нове повідомлення сервер розсилає соціальним каналом кімнати лише як сигнал, і кожна
відкрита сторінка перечитує чат із Relay, тож підробити чужі слова через канал не вийде. Непрочитане видно числом на
кнопці й бульбашкою «💬 N» над стійкою; що прочитано, браузер пам'ятає. Пишеш під своїм іменем у кафе; поки його нема,
чат спершу питає ім'я.

Назва кафе (поле в «Кафе росте»): стоїть на вивісці й на даху будинку замість RELAY, а в заголовку будинку замість
«інтернет-кафе». Лежить в `interior.title` разом з рештою кафе, тож бачать її всі. Чат, що замовк посеред ходу (Esc,
Ctrl+C, закритий ноутбук), за 5 хвилин без подій перестає рахуватись роботою, і агенти в залі вільні.

Прості слова (`lib/live/plain.ts`, `lib/live/speech.ts`). Кожен виклик інструмента несе `say`: дію, вид того, з чим
працює агент, і людську назву (`EditProfileScreen.tsx` → «екран Edit Profile»). Список агентів, журнал, картки й
бульбашки складають з неї фразу мовою глядача: «малює новий екран «Edit Profile»», «запускає тести», «дивиться задачу».
Вибір укр / eng / рус або «технічно» (файли й команди, як раніше) поруч із музикою, браузер його пам'ятає. Перекладено
лише те, що роблять агенти; решта сторінки українською.

Токени й ліміти. Хуки на `Stop`, `SubagentStop` і `SessionEnd` рахують токени з транскрипту (`plugin/scripts/relay.sh`):
вхід, запис і читання кешу, вихід. Кожне повідомлення асистента рахується один раз, субагент цілком, коли зупинився,
головний чат лише приріст з минулого разу (зсув у `~/.local/state/relay/usage/<сесія>`). Числа йдуть після рядка
`#relay-usage`, сервер бере їх лише з подій кінця ходу. `relay_hourly` тримає їх погодинно, по агентах, чатах і людях
(`supabase/migrations/0009_tokens.sql`). Ліміти 5 годин і тижня Claude Code віддає лише статус-рядку (`rate_limits`,
лише Pro/Max): `relay.sh statusline` зберігає їх у `~/.local/state/relay/limits`, а хуки на питанні й відповіді шлють
останні після `#relay-limits`. Чи запускає статус-рядок десктоп-застосунок, документація не каже. Тому є ще хук
`StopFailure`: коли хід обірвався на `rate_limit`, у шапці червоне «ліміт вичерпано», на залі «! ліміт», сповіщення й
пуш кажуть те саме, а в підсумку пояснення, що коли ліміт скинеться, Claude Code не повідомляє. Назва чату приходить і з
транскрипту (`#relay-title`), і просто з `session_title` у самому хуку, тож зали названі як чати навіть зі старими
хуками. `relay.sh` шле свою версію після `#relay-v`; якщо в останній твоїй події її нема, сторінка просить оновити
підключення тією самою фразою. На сайті: токени в шапці й у картці агента, стоси паперу на столах, табло «ток/хв» під
вивіскою, «Токени» й «Ліміти підписки» в підсумку, досягнення «Мільйон токенів» і «Мільярд токенів».

Сцена клікабельна (`components/cafe/hit.ts`): агент відкриває картку (що робить, останні 5 дій, час у роботі, токени),
кіт муркоче, дошка відкриває підсумок, автомат прогрес кафе, вікно перемикає тему, двері запрошують команду. Агенти й
журнал виїжджають шторками, кнопка в шапці сцени розгортає її на весь екран.

Присутність і реакції (`lib/live/useSocial.ts`): у хмарному режимі кожна відкрита вкладка кафе відмічається в Realtime
presence на окремому каналі `relay-social:<кімната>`, не на каналі подій. Хто ще дивиться, видно в шапці сцени, а
перші троє сидять на барних стільцях (`components/cafe/guests.ts`). З картки агента можна кинути реакцію (👏 🔥 ☕ ❤️ 😂
🎉): вона летить broadcast-ом усім у кафе й спливає над його столом з іменем того, хто кинув. Нічого не зберігається;
чужі повідомлення проходять перевірку (`lib/live/social.ts`). Глядач за посиланням теж може кидати реакції. Локальний
Relay показує реакції лише в самій вкладці.

Ігри (кнопка з джойстиком у шапці сцени, `components/live/GamesPanel.tsx`), поки агенти працюють:

- «Ставки» (`lib/live/useBets.ts`): коли Claude доручає задачу субагенту, під сценою з'являється ставка, скільки той
  працюватиме: до 2 хв, 2–8 хв чи довше. Ставки приймаються 90 секунд, результат видно, щойно субагент зупинився.
- «Лови чашки» (`components/games/CatchCups.tsx`): 30 секунд бариста кидає чашки, тацю ведеш мишкою, пальцем або
  стрілками; золота чашка дає три.
- «Удвох» з кимось, хто теж зараз у кафе: запрошення спливає в нього плашкою (`lib/live/useDuels.ts`).
  Пінг-понг до 5 очок (`components/games/Pong.tsx`) і хрестики-нулики (`lib/live/useTicTacToe.ts`).

Ставки, запрошення й ходи хрестиків-нуликів летять тим самим каналом `relay-social:<кімната>` (`lib/live/bus.ts`).
Пінг-понг відкриває свій канал на партію, `relay-pong:<кімната>:<гра>`, щоб решта кафе не отримувала кожен рух ракетки.
Кожен гравець вирішує, чи відбив він м'яч своєю ракеткою, і каже про це іншому. Між цими повідомленнями обидва ведуть
той самий м'яч, а отримане зсувають на половину виміряного часу туди й назад (`lib/live/pong.ts`). У базу пишеться лише рахунок:
`relay_scores` через `relay_score_add` (лише з ключем, не частіше разу на 2 с на гравця й гру, до 300 рядків на
кімнату, `supabase/migrations/0010_games.sql`). За посиланням для перегляду грати можна, але рахунок не пишеться.
Локально рахунок лежить у `localStorage`, а хрестики-нулики потребують хмарного режиму.

Інтер'єр і кавові зерна. Робота Claude приносить кафе зерна (`lib/live/interior.ts`): питання 3, доручення 5,
відповідь 1, хвилина в роботі 1, кожні 4 дії ще одна, досягнення 30. Рахуються вони з тих самих лічильників, що й
досягнення, тож нічого окремо не зберігається. За зерна в магазині («кафе» → «Магазин») купуються 17 речей: свічка,
кактус, кіт-манекі й бонсай на підвіконня; три постери на стіну; килимок; на підлогу лежак для кота, торшер, пальма,
книжкова шафа, грамофон, диван і музичний автомат (`components/cafe/furniture.ts`). Ще дві речі одна на кафе: неонова
вивіска, на якій можна написати свій другий рядок замість «інтернет-кафе», і другий кіт, сірий, зі своїм ім'ям. Куплену
річ ставиш клацанням на сцені: зелена рамка означає, що місце вільне, червона, що ні. Поставлену можна перетягнути
мишею або клацнути й вибрати «перемістити» чи «прибрати». Зароблений декор (аркадний автомат, акваріум, рослина в
кутку, сова) рухається так само, а «на звичне місце» повертає його туди, де він стояв. Столи в кожному чаті стоять
по-своєму, тож річ, якій заважає стіл, відступає на найближче вільне місце (`components/cafe/placement.ts`). У картці
агента можна змінити йому зачіску, колір волосся, шкіри й одягу, річ на столі (кактус, качка, банки, книжки, лампа або
нічого) і дати табличку з ім'ям, яка заміняє його назву над столом. Одяг за столом видно лише краєм, повністю тоді,
коли агент ходить. Усе це лежить у
`relay_rooms.interior` (`supabase/migrations/0011_interior.sql`), тож глядач за посиланням бачить те саме кафе.
Локально інтер'єр лежить у `localStorage`.

Теми: нічне кафе (дощ і місто), космічна станція (панелі, планета в ілюмінаторах, зорі пливуть), лісовий табір
(колоди, ялини, світлячки) і зимовий вечір (сніг на дахах і за вікном). Палітри лежать у `components/cafe/theme.ts`,
вікна й погода в `components/cafe/windows.ts`. Тему обирають у вікні «кафе»; вона зберігається в `relay_rooms.theme`
поруч з ім'ям кота, тож глядач за посиланням бачить ту саму. Локально тема лежить у `localStorage`.

Плагін Claude Code (`plugin/`) ставить ті самі хуки, але `settings.json` не чіпає: посилання на кафе лежить у
`~/.config/relay/hook-url` (права 600). Його записує `/relay:connect <посилання>`, а `/relay:status` показує, куди
йдуть події. Без посилання хук мовчки нічого не шле. Сайт сам роздає маркетплейс: `/plugin marketplace add
<сайт>/marketplace.json` (`app/marketplace.json/route.ts` віддає архів `public/relay-plugin.zip` з sha256; потрібен
Claude Code 2.1.224 або новіший). Після змін у `plugin/` перепакуй: `npm run plugin:pack` (той самий вміст дає той
самий sha256). Локально плагін береться прямо з репозиторію: `claude plugin marketplace add ~/relay`,
`claude plugin install relay@relay`, а в чаті `/relay:connect local`. Вимкнути: `/plugin disable relay`.

Потрібні ще три змінні: `NEXT_PUBLIC_VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`
(ключі: `npx web-push generate-vapid-keys`). Без них сайт працює, просто без пушів.

### Локально (нічого не йде в мережу)

Для власника репозиторію: інструкція для Claude лежить у [`public/setup.md`](public/setup.md). Руками:

```bash
git clone https://github.com/justbios/agent-pipeline-viz.git ~/relay
cd ~/relay
npm install
npm run setup         # хук у ~/.claude/settings.json + Relay у фоні на http://127.0.0.1:3737
```

| Команда | Що робить |
|---|---|
| `npm run setup` | `hooks` + `up` |
| `npm run hooks` / `npm run unhook` | додає / прибирає хук у `~/.claude/settings.json` (або `$CLAUDE_CONFIG_DIR`) і кладе скрипт у `~/.config/relay/relay.sh`. Решту налаштувань не чіпає, бекап `settings.json.bak-relay`, повторний запуск нічого не міняє. `node scripts/install-hooks.mjs --statusline` додає статус-рядок для лімітів, наявний лишає зі своїм виводом |
| `npm run up` / `npm run down` | збирає й тримає Relay у фоні (лог `data/server.log`) / зупиняє. `npm run up -- --restart` після `git pull` |
| `npm run live` | те саме на передньому плані, в терміналі |

Сторінка сама обирає режим: на `127.0.0.1` / `localhost` вона читає локальний Relay, на будь-якому іншому домені
хмарну кімнату. Хуки обох режимів живуть у `lib/live/hookConfig.mjs`. Вони асинхронні (`async: true`), мовчазні й
завжди виходять з 0: не гальмують агентів, не витрачають токенів, а коли адресат недоступний, curl тихо падає.

Події тримаються в пам'яті процесу Relay (і в `data/live-events.jsonl`, щоб пережити перезапуск) і нікуди з машини не йдуть. Перевірити без
справжнього Claude можна так: `node scripts/simulate-claude.mjs` програє вигадану сесію.

```
Claude Code hooks ──curl──▶ /api/claude-hook ──▶ lib/live/store (пам'ять)
                                                        │ SSE /api/live
                                                        ▼
                         useLiveFeed → buildLiveModel → CafeScene
```

## Як воно влаштоване

```
Оркестратор (Claude Agent SDK)         Next.js фронт
  emit(start|tool_call|handoff|…)         PipelineStage  ← анімований конвеєр
        │                                 ActivityLog    ← потік подій
        ▼                                 AgentRoster    ← статуси агентів
   Supabase: agent_events  ──realtime──▶  useAgentEvents(runId)
```

Один контракт на все — таблиця `agent_events`. Фронт малює те, що в ній є, і не знає,
звідки взялися події (SDK, Claude Code хуки, будь-що).

### Ключові файли

| Файл | Що це |
|---|---|
| `lib/types.ts` | тип події + опис 8 агентів (імена, ролі, кольори, іконки) |
| `lib/mockRun.ts` | детермінований змодельований прогін для replay-демо |
| `lib/useReplay.ts` | rAF-годинник, що програє прогін (play/pause/швидкість/цикли) |
| `lib/stage.ts` | геометрія конвеєра + стан вузлів і позиція пакунка з годинника |
| `components/PipelineStage.tsx` | анімований конвеєр (SVG-трек, вузли, пакунок) |
| `components/ActivityLog.tsx` | термінальний потік подій |
| `components/AgentRoster.tsx` | список агентів з живими статусами |
| `lib/cafe/*`, `components/cafe/*` | інтернет-кафе: розсадка, маршрути, модель сцени, піксельний рендер, кіт |

| `supabase/migrations/0001_agent_events.sql` | схема таблиць + RLS + realtime |

## Стара заготовка: оркестратор Agent SDK (не підключена)

До хмарного режиму вище не має стосунку: окремі таблиці `agent_events` і `/api/ingest`, у проєкті `relay` їх немає.

1. Створи проєкт у Supabase, застосуй `supabase/migrations/0001_agent_events.sql`.
2. Заповни `.env` (див. `.env.example`).
3. У `PipelineDashboard` заміни `buildMockRun()` на `useAgentEvents(runId)` і
   збери `timings` з подій замість моку (події вже в правильному форматі).
4. Запусти оркестратор з `orchestrator/` — він пише `agent_events`, фронт оживає.
