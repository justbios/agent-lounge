# Agent Lounge — живий конвеєр агентів

> Раніше проєкт звався **Relay**. Внутрішні назви лишились старими, щоб не зламати вже підключених: таблиці й функції
> `relay_*` у базі, ключі `relay.*` у браузері, `~/.config/relay` і скрипт хуків `relay.sh`.
>
> Agent Lounge — незалежний проєкт, не пов'язаний з Anthropic. «Claude» і «Claude Code» — торгові марки Anthropic.
> Ліцензія: [Apache-2.0](../LICENSE); ігри в `public/roms/` мають власні ліцензії ([THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md)).

Гейміфікована візуалізація мультиагентного пайплайну: 8 агентів по черзі беруться
за роботу і передають «пакунок» один одному, а глядач бачить це в реальному часі —
з подіями, статусами, рівнями та лічильником передач.

Два режими:

- **демо**: піксельне інтернет-кафе на змодельованому прогоні. Кубик 🎲 перемішує
  столи й бере випадковий склад агентів.
- **наживо**: твої справжні сесії Claude Code. Головний Claude сидить за своїм столом;
  коли він запускає субагента, то встає й несе йому задачу, субагент працює (над
  головою хмарка з поточною дією), а потім приносить результат назад.

## Наживо: підключити свій Claude Code

Два способи, і обидва — одна фраза для свого Claude Code.

### Хмарно, через свій сайт

Сторінка `/connect` твого розгорнутого сайту (Vercel + свій Supabase, налаштування нижче) видає особистий ключ і готову фразу з хуками. Claude
дописує їх у `~/.claude/settings.json`, і далі агенти видно на сайті, з будь-якого пристрою (посилання
`/#k=<ключ>`). Фраза кладе короткий скрипт хуків у `~/.config/relay/relay.sh` (сайт віддає його як `/relay.sh`, а
фраза звіряє sha256) і, якщо можна, додає статус-рядок для лімітів.

```
Claude Code hooks ──curl, x-relay-key: <ключ>──▶ Vercel /api/claude-hook ──▶ normalize ──▶ Supabase rpc relay_ingest
                                                                           │ realtime.send(relay:<топік>, private)
сторінка: rpc relay_snapshot (знімок) + приватний Realtime-канал ◀─────────┘
```

- Потрібен свій Supabase-проєкт з міграціями з `supabase/migrations/` (основна схема в `0003_live_rooms.sql`).
- Таблиця закрита RLS, ходять лише дві функції за ключем. Кімната — це `sha256(ключ)`, сам ключ ніде не лежить.
- Події живуть добу (pg_cron) і не більше 12000 на кімнату. Відкрите кафе отримує всі репліки, передачі
  й відповіді дня та останні 3000 дій інструментів, тож ранок дня не губиться.
- Ключ кімнати `relay.sh` шле в заголовку `x-relay-key`, а не в адресі, яку пишуть у журнали сервери й проксі.
  Адреса з `?k=` ще працює для старих скриптів.
- Канал кімнати приватний (`0021_security.sql`): браузери можуть його лише слухати, пише туди тільки база. Хто знає
  топік (наприклад, з посилання на перегляд), не підкине в чуже кафе фальшивих подій.
- У події кафе йде лише нормалізоване: короткі описи дій, імена агентів, назва папки. Вміст файлів і повні тексти
  відкидаються одразу у `lib/live/normalize.ts`. Виняток — режим «Я не за комп'ютером» нижче: поки він увімкнений,
  запит дозволу, питання чи план лежить у `relay_asks` цілим (уся команда, вміст файлу для Write/Edit, текст плану),
  бо його треба показати на телефоні. Через добу текст стирається, сам запис — через 30 днів.
- Кімната приймає до 600 подій за хвилину, а весь сайт — до 200 нових кімнат за годину (`relay_ingest`).
- Хуки на `UserPromptSubmit` і `SessionStart` додають список файлів з `.claude/agents`, тож за столи сідає вся
  команда, навіть хто ще не працював.
- Windows без Git Bash: `sh` там нема, тож сайт дає іншу фразу, з HTTP-хуками (`httpHookSettings` у
  `lib/live/hookConfig.mjs`). Claude Code сам шле подію на `/api/claude-hook?…&via=http`, а той відповідає 204
  одразу й пише в кафе через `after()`, бо такий хук тримає Claude до відповіді. Назв чатів, токенів і лімітів у
  цьому режимі нема: їх читає скрипт.
- На сторінці підключення блок «Стан підключення» (`components/connect/HookStatus.tsx`) наживо показує, чи дійшла
  перша справжня подія від твого Claude, і що перевірити, якщо ні.
- Змінні для Vercel: `NEXT_PUBLIC_SUPABASE_URL` і `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` (див. `.env.example`).

#### Сайт лише для себе

Розгорнутий сайт за замовчуванням дає ключ і кафе кожному, хто відкриє `/connect`. Щоб він був лише твоїм:

1. Застосуй `supabase/migrations/0022_private_cafe.sql` і в SQL-редакторі Supabase виконай
   `select public.relay_private(true);`. Відтепер кімната, якої сайт ще не бачив, не може слати події, тримати кота,
   чат, рахунок ігор, пуші чи особисті ключі: база відповідає `cafe closed`, а хук отримує 410. Кафе, які сайт уже
   знає, їхні ключі, особисті ключі й командні запрошення працюють як раніше. Відкрити знову:
   `select public.relay_private(false);`.
2. Додай у Vercel `NEXT_PUBLIC_RELAY_PRIVATE=1` і передеплой (змінна вшивається під час збірки). Браузер без ключа
   й без запрошення побачить на `/connect`, у порожньому кафе й біля дверей «Це особисте кафе» з посиланням на
   проєкт і командами, як завести своє, а не новий ключ. Свій ключ на новому пристрої: посилання з `#k=` або поле
   «Це твоє кафе?».

Сама змінна лише ховає видачу ключів: публічний ключ Supabase дістає до `relay_ingest` напряму, тож тримає саме
база. Нове кафе для себе (окреме командне чи «нове порожнє кафе») на закритому сайті: відкрий його, дочекайся першої
події від Claude у новому кафе і закрий знову, воно лишиться відкритим.

#### «Потрібна твоя увага»

Коли Claude просить дозвіл (`Notification`) або закінчив хід (`Stop`), чат отримує стан, який видно звідусіль:

- на вкладці чату жовтий «! чекає», зелений «✓ відповів» або червоний, якщо хід обірвався (ліміт, помилка), у
  заголовку сторінки `(N)`;
- над кафе дошка всіх чатів за останні години (`components/live/ChatBoard.tsx`): ті, що чекають на тебе, зверху, далі
  обірвані, «твоя черга», ті, що працюють, і решта, у кожного остання дія; клік відкриває його залу. Поки Claude десь
  чекає на тебе, її верхній рядок стає жовтою табличкою «Claude чекає на тебе» з тим, чого саме, і лишається, доки ти
  не відповіси. Дошку можна згорнути, табличка лишається;
- у кафе агент піднімає руку, на моніторі блимає «!», над столом жовта табличка з тим, чого він чекає;
- кнопка з дзвіночком: звук (поки сторінка відкрита) і веб-пуш на телефон чи комп'ютер, навіть із закритим сайтом.
  Звук свій для кожного випадку (`lib/live/chime.ts`): дверний дзвоник із трьох нот, коли Claude чекає на тебе, і ще
  двічі, через 3 і 6 хвилин, якщо ніхто не відповів; дві ноти вгору, коли він відповів; дві вниз, коли хід обірвався.
  На iPhone пуш працює лише з іконки на початковому екрані (маніфест `app/manifest.ts`, воркер `public/sw.js`).

Щоб «чекає» зникало саме тоді, коли ти відповів, а не з наступним кроком Claude, `relay.sh` 8 на `Notification` про
дозвіл чи питання (або коли питання пішло в кафе) ставить позначку в `~/.local/state/relay/waits/<чат>`, а `relay.sh answered` на `PostToolUse` того
самого агента прибирає її й шле в кафе лише назви чату, агента й інструмента (подія `answered`, якої не видно в
журналі). Без позначки він нічого не шле, тож результати інструментів комп'ютер не покидають.

Пуш іде з того самого хука: `/api/claude-hook` відповідає 204 одразу, а через `after()` бере пристрої кімнати
(`relay_push_targets`) і шле їм `web-push`. Хто хоче лише дозволи, отримує їх одразу, а «Claude відповів» через
хвилину тиші, коли Claude Code сам шле нагадування. Хто ввімкнув «одразу, щойно відповів», отримує `Stop` без
затримки. Пристрої, які зникли (404/410), вимикаються прапорцем `active`. Схема `supabase/migrations/0004_push_subs.sql`.
Кнопка «поділитися» в шапці записує 15-секундний кліп кафе (`components/cafe/clip.ts`: `captureStream` +
`MediaRecorder`; підписи, бульбашки й вивіска перемальовуються в кадр у `overlay2d.ts`, бо на сайті вони DOM),
звичайний (сцена в 3×) або вертикальний 9:16 для TikTok, Reels і Shorts (1080×1920: сцена в цілому масштабі, рядок
над нею й адреса проєкту під нею, `drawTall`). Кліпи й картка дня підписані адресою проєкту `PROJECT_URL` з
`lib/brand.ts`, а не адресою сайту, тож копія на своєму сервері чи локальна веде глядачів до репозиторію. Ще кнопка
дає посилання лише для перегляду `/#v=<sha256(ключ)>`. Воно читає ту саму кімнату через `relay_snapshot_room`
(`supabase/migrations/0005_view_links.sql`), але без ключа: писати в кімнату чи вмикати пуші глядач не може.
Закрити доступ можна лише новим ключем.

«Підсумок» на «наживо» показує день і тиждень: питання, дії, доручення, активні хвилини, чати, серію днів, топ
агентів, інструментів і проєктів. Цифри лежать у погодинних лічильниках `relay_hourly`: їх веде тригер на
`relay_events` (`supabase/migrations/0006_hourly_recap.sql`), який ловить будь-яку свою помилку, тож запис подій
зламати не може. Лічильники переживають добове прибирання подій. Локальний Agent Lounge рахує те саме з пам'яті
(`lib/live/recap.ts`). Звідти ж «програти цей чат у 10×» (паузи стиснуті до 15 с) і картка дня PNG 1080 завширшки (висота за вмістом).

Досягнення (кубок у шапці): 30 за весь час (`lib/live/achievements.ts`), рахуються з тих самих погодинних лічильників,
розкладених по локальних днях (`relay_progress`, `supabase/migrations/0007_cafe_progress.sql`). Перші шість навчають
прийомів Claude Code: режим плану, список справ, скіл, пошук у мережі, питання з варіантами й три агенти за годину.
Їх видно з інструментів кожного дня (`kinds` і `crowd`, `supabase/migrations/0018_learn_kinds.sql`). Дев'ять із них
ставлять у кафе річ: гірлянду, сову на підвіконні, кубок на автоматі, вогнегасник, аркадний автомат, акваріум,
золоту кавоварку, рослину в кутку й корону коту (`components/cafe/decor.ts`). Нове досягнення показується плашкою
один раз на браузер (`relay.seenAch`); ті, що вже були до першого відкриття, записуються мовчки. Ім'я кота
зберігається в `relay_rooms` через `relay_room_set` (лише з ключем, до 24 символів), тож його видно й за
посиланням для перегляду. Локально ім'я лежить у `localStorage`, а прогрес рахується з подій у пам'яті.

«Командне кафе»: кілька людей підключають своїх Claude до одного ключа, і кожен хук несе ім'я учасника
(`/api/claude-hook?k=<ключ>&m=<ім'я>`, `lib/live/member.ts` чистить його до 24 символів). Коли в кімнаті
з'являється більше одного автора, сторінка ділить її за людьми (`lib/live/team.ts`): у будинку кожен має свій
поверх, а в лобі внизу «уся команда», де за столами сидять самі учасники (`lib/live/teamModel.ts`; хто мовчить
5 хвилин посеред ходу, засинає). У залі над сценою лишається смужка учасників, щоб перейти до чужого чату. Запрошення `/connect#team=<ключ>` дає повний доступ до кафе, тож лише для своїх.
Звук, заголовок і пуші стосуються тільки твого Claude: пристрій запам'ятовує учасника
(`relay_push_subs.member`, `supabase/migrations/0008_team_push.sql`), і чужі запити дозволу його не будять.
Браузер пам'ятає всі відкриті кафе, тож особисте не губиться, коли приєднуєшся до команди.

Особисті ключі (сторінка підключення, крок «Особисті ключі»): хто їх вмикає, стає власником кафе, а спільний ключ
одразу перестає діяти, тож кожен один раз віддає своєму Claude нову фразу. Далі власник створює кожному запрошення
`/connect#team=<особистий ключ>` з іменем, яке не підробити: `relay_ingest` і `relay_chat_add` підписують події й
повідомлення іменем ключа, хоч би що прийшло в `&m=`. Власник може прибрати людину: її ключ відкликається, пуші на її
пристрої вимикаються, а канал Realtime і посилання для перегляду кафе переходять на нову таємну назву
(`relay_rooms.alias`), тож прибраний більше не бачить кафе й не пише в нього; відкриті сторінки решти дізнаються про
це подією `rekey` і питають `relay_whoami`, куди тепер слухати (`lib/live/access.ts`). Кафе, зерна, меблі й чат при
цьому лишаються. Схема в `supabase/migrations/0014_personal_keys.sql` (таблиця `relay_keys` зберігає лише sha256
ключів); кафе на спільному ключі працюють, як раніше.

Будинок (`components/live/House.tsx`, `lib/live/house.ts`). Замість рядка вкладок кафе показано будинком у розрізі:
кожен чат за останні 6 годин є окремою залою, і всі зали живі одночасно (`components/cafe/MiniCafe.tsx` малює ту саму
сцену дрібно, вісім разів на секунду, без імен і бульбашок). Соло-кафе ставить по три зали на поверх, найсвіжіші
внизу; командне дає поверх кожній людині, твій найнижче. Зала, де Claude чекає на тебе, світиться «! чекає». Клік
наближає залу до повної сцени (View Transitions, а де їх немає, просто перемикає), кнопка з будиночком у шапці
віддаляє назад. Будинок з'являється, коли чатів хоча б два або в кафе є команда; вибір «будинок чи зала» браузер
пам'ятає, а пуш завжди відкриває свою залу.

«Поки тебе не було» (`lib/live/away.ts`, `components/live/AwayCard.tsx`). Браузер раз на хвилину, поки кафе на
екрані, і щоразу, коли вкладку ховають, пише собі, коли ти востаннє дивився на це кафе (окремо для кожного кафе й
посилання на перегляд). Коли повертаєшся після 20 хвилин або більше, над кафе плашка: скільки за цей час було питань,
відповідей, доручень агентам, дій і невдалих спроб, скільки пішло токенів, кому з агентів доручали найбільше, хто з
команди скільки питав, і кнопки чатів, які зараз чекають саме на тебе (❓ питання або дозвіл, ✓ твоя черга). Кнопка
відкриває залу цього чату. Коли кафе вже не пам'ятає всіх подій від того часу, плашка про це каже.

«Я не за комп'ютером» (`lib/live/useAsks.ts`, `components/live/AskCard.tsx`, `app/api/claude-ask/route.ts`,
`app/api/claude-away/route.ts`, `supabase/migrations/0019_asks.sql`, `0020_ask_answers.sql`, `0021_security.sql`,
`0023_ask_words.sql`).
Працює лише з особистим ключем і лише для своїх чатів. Вмикається тільки на самому комп'ютері:
`/agent-lounge:away on` у Claude Code або `sh ~/.config/relay/relay.sh away on` у терміналі (на 12 годин), або
`away always`, і тоді назавжди, до `away off`: кожне питання спершу чекає на кафе. Сайт може лише вимкнути його
(«я повернувся»), тож ніхто з твоїм ключем не змусить Claude чекати на кафе. З `always` «я повернувся» лише віддає
терміналу те питання, що чекає зараз, а наступне знову прийде в кафе.

Поки режим увімкнений, запит дозволу від Claude приходить у кафе й пушем: що саме він хоче зробити (уся команда, файл
чи адреса, а для Write/Edit ще й вміст під «що саме зміниться») і кнопки «дозволити раз» і «заборонити». Так само
приходять його питання з варіантами відповіді і план (видно весь текст, кнопки «затвердити план» і «ні, хай планує
далі»). Картка показує одне питання за раз, те, що чекає найдовше, і скільки ще за ним. Варіант, який радить Claude
(він закінчує його назву на «(Recommended)»), позначено «★ радить Claude». Під кожним питанням є «✎ свій варіант»: в
питанні з одним вибором він замінює варіант, у питанні з кількома додається після них, і Claude отримує «варіант,
варіант, твій текст». До «ні» на дозвіл чи план можна «✎ пояснити»: Claude прочитає це після речення про відмову, а
«дозволити» тоді вимкнено, щоб написане не загубилось. Обидва тексти до 1000 символів.

Поки режим увімкнений, локальний хук перевірки (`relay.sh checkin` на `UserPromptSubmit`) додає до кожного твого
повідомлення незмінне речення: ти відповідаєш з телефона, тож коли Claude потрібне твоє рішення, хай питає своїм
інструментом питань, варіантами і своїм вибором першим, а не текстом у кінці відповіді, на який кафе відповісти не
може. Хуки `PermissionRequest` і `PreToolUse` на `AskUserQuestion|ExitPlanMode` (`relay.sh ask`, єдині, на які
Claude чекає) до 10 хвилин питають сайт, чи є відповідь.

Відповідь приймає сам комп'ютер, а не сервер. `relay.sh pair` (або `/agent-lounge:away pair`) кладе посилання
`<сайт>/#pair=<секрет>` у буфер обміну; його відкривають на телефоні, і браузер тримає секрет у себе. Секрет лежить
тільки в `~/.config/relay/answer-key` (права 600) і в браузерах, які спарено. Кожна відповідь — це
HMAC-SHA256(секрет, `id:allow|deny:sha256(JSON хука):u`), де JSON хука — рівно те, що скрипт надіслав, а `u` — вхід,
який Claude отримає назад (відповіді на питання чи план). Телефон показує запит, прочитаний з цього ж JSON, а не з
того, що сервер поклав поруч. `relay.sh` перераховує підпис і без збігу нічого не відповідає: питає термінал. Тож
сервер, база чи будь-хто з ключем кафе не може ні дозволити за тебе, ні підмінити команду чи план, які ти бачиш.
Кожна відповідь з кафе пишеться в `~/.local/state/relay/answers.log`; `/agent-lounge:status` показує останні, а
відкинуті позначені `unsigned:`. Скрипти старші за 6 віддаленої відповіді не отримують.

Без відповіді, коли режим вимкнено, або коли сайт недоступний, хук нічого не відповідає, і питає термінал, як завжди.
Поки хук на питання чи план чекає, термінал цього питання не показує: «я повернувся» відпускає його одразу і вимикає
режим і на комп'ютері (крім `away always`). «Дозволити завжди», змінена команда чи змінений план звідси неможливі, а
правила заборони в Claude Code діють і далі. Свій текст іде лише як відповідь на питання чи пояснення до «ні»; почати
з Claude нову розмову звідси не вийде: відкритий чат у терміналі приймає лише те, що ввели там (для цього в Claude
Code є Remote Control). На Windows без Git Bash
хуків-скриптів немає, тож цей режим там не працює. Детальніше про модель загроз: [SECURITY.md](../SECURITY.md).

Рідкісні гості (`lib/live/visitors.ts`, `components/cafe/visitor.ts`, `components/cafe/VisitorTag.tsx`). Десь раз
на три години в кафе заходить незвичайний відвідувач: кур'єр з піцою або золотий кіт, а раз на п'ятсот візитів
блискучий агент. Він іде від дверей до останнього стільця за стійкою, сидить там кілька хвилин (над ним підпис) і йде.
Хто й коли заходить, рахується з годинника, без бази: той самий гість з'являється в усіх кафе Agent Lounge водночас, тож усі,
хто дивиться одне кафе, бачать одне й те саме. Коли всі шість стільців зайняті або кафе на ніч зачинене, гість не
заходить. Гостьова книга в «Досягненнях» пам'ятає в цьому браузері, кого ти вже бачив і коли вперше.

Зали підписані так само, як чати в Claude Code («Баг пайплайн», «Jira ticket SCRUM-30»), а не іменем папки.
Claude Code щоходу дописує назву чату в транскрипт (`"customTitle"`), і хуки на початку сесії, питанні, відповіді та
сповіщенні беруть її з останнього мегабайта транскрипту й шлють після рядка `#relay-title`
(`lib/live/hookConfig.mjs`, `plugin/scripts/relay.sh`). Без назви зала лишається з іменем папки. Щоб назви з'явились,
хуки треба оновити: ще раз віддати Claude фразу зі сторінки підключення, `npm run hooks` локально або оновити плагін.

Кафе живе за годинником того, хто дивиться (`components/cafe/daylight.ts`): світанок з 5:30, день з 8:00, вечір з
18:30, ніч з 22:00. Вдень у вікнах блакитне небо з сонцем і в залі світліше, на світанку й увечері низьке червоне
сонце, уночі місяць і зорі. Уночі, поки агенти працюють, неон пише «нічна зміна». Кафе зачиняється, лише коли всі
чати мовчать понад годину і Claude тебе не чекає: неон гасне й пише «зачинено до ранку», на дверях табличка,
бариста йде додому, агенти дрімають. Порожнє кафе, куди ще не прийшла жодна подія, не зачиняється ніколи. Агенти без роботи щось роблять
(`components/cafe/idle.ts`): за 15 секунд після готового читають книжку, грають у карти чи дрімають, кожні 40 секунд
щось інше. Передача задачі тепер видна через усю залу: паперовий літачок злітає зі столу того, хто доручає, летить із
хвостом і тінню на підлозі й падає зі спалахом на стіл того, хто отримав (`components/cafe/flight.ts`). Музичний
автомат (`lib/live/music.ts`, `lib/live/tracks.ts`, `components/live/Jukebox.tsx`) відкривається кліком по самому
автомату в кафе або нотою у верхній панелі. На ньому п'ять платівок, які браузер складає на льоту, без жодного файлу:
«Lo-fi вечір», «Дощ за вікном» (піаніно під шум дощу), «Джаз-кафе» (свінг, контрабас, райд), «Нічне місто» (синтвейв) і
«8 біт», а ще «Лише клавіатури» без музики. Клік по платівці ставить її, клік по тій, що грає, ставить на паузу;
повзунок задає гучність. Над автоматом у сцені пливе назва того, що грає. Чим більше агентів працює (у будинку: скільки
зал активні), тим гучніше гурт і тим частіше клацають клавіатури; коли не працює ніхто, клавіатури замовкають. Звук
вимкнений, поки його не ввімкнеш, і браузер пам'ятає платівку й гучність. Платівка в кафе одна на всіх: хто її
поставив, той і вибрав музику для кожного, у кого ввімкнено звук. Вибір летить подією `juke` каналом
`relay-social:<кімната>` і їде в presence кожної відкритої вкладки, тож сторінка, відкрита пізніше, одразу грає те саме
(`lib/live/useSocial.ts`); у базу нічого не пишеться. Біля платівки видно, хто її поставив. Звук і гучність у кожного
свої. За посиланням для перегляду платівку лише слухають, а поки ніхто нічого не ставив, грає власний вибір браузера.

Перерви (`components/cafe/outing.ts`, `outingSprites.ts`). Агент, що відпочив після роботи, на початку кожного
двохвилинного слоту з імовірністю 1/2 встає з-за столу: іде до бару по каву, до автомата по банку, сідає на диван
(двоє на одному дивані балакають), грає на аркаді чи ставить платівку на джукбоксі, потім вертається й п'є за столом.
Місця роздаються на слот, тож двоє не стають в одне. Усе виводиться з годинника й стінтів, тому всі глядачі бачать те
саме. Питання від Claude («! чекає») одразу повертає агента за стіл, а «✓ відповів» ні. Уночі, коли кафе зачинене,
ніхто не виходить. Коти час від часу сплять на поставленій лежанці, по одному.

Бар і чат (`components/cafe/guests.ts`, `lib/live/useChat.ts`, `components/live/ChatPanel.tsx`). Біля бару шість
місць: три стільці біля стійки й три біля високого столика перед нею. Сідають усі, хто відкрив кафе, і ти теж
(підписаний «ти»), у тому самому порядку на кожному екрані; кому не вистачило місця, той «+N». Клік по бару або кнопка
з бульбашкою в шапці відкриває груповий чат кафе. Повідомлення лежать у `relay_chat` під кімнатою
(`supabase/migrations/0012_chat.sql`): пишуть ті, в кого є ключ, читають також за посиланням для перегляду, не частіше
20 повідомлень на хвилину на кафе. Нове повідомлення сервер розсилає соціальним каналом кімнати лише як сигнал, і кожна
відкрита сторінка перечитує чат із Agent Lounge, тож підробити чужі слова через канал не вийде. Непрочитане видно числом на
кнопці й бульбашкою «💬 N» над стійкою; що прочитано, браузер пам'ятає. Пишеш під своїм іменем у кафе; поки його нема,
чат спершу питає ім'я.

Назва кафе (поле в кав'ярні, розділ «Твоє кафе»): стоїть на вивісці й на даху будинку замість RELAY, а в заголовку будинку замість
«інтернет-кафе». Лежить в `interior.title` разом з рештою кафе, тож бачать її всі. Чат, що замовк посеред ходу (Esc,
Ctrl+C, закритий ноутбук), за 5 хвилин без подій перестає рахуватись роботою, і агенти в залі вільні.

Прості слова (`lib/live/plain.ts`, `lib/live/speech.ts`). Кожен виклик інструмента несе `say`: дію, вид того, з чим
працює агент, і людську назву (`EditProfileScreen.tsx` → «екран Edit Profile»). Список агентів, журнал, картки й
бульбашки складають з неї фразу мовою глядача: «малює новий екран «Edit Profile»», «запускає тести», «дивиться задачу».
Мова в шапці: English, українська, русский або «технічно» (файли й команди, як раніше); браузер її пам'ятає, а при
першому відвідуванні бере мову самого браузера. Технічні рядки, які пише саме кафе («читає colors.ts», «чекає на
дозвіл: bash»), подія несе ще й по частинах (`tech`: дія й файл), тож і вони йдуть мовою глядача (`lib/live/tech.ts`). Інтерфейс кафе (`lib/i18n.ts`: `useTr()`, `tr(ui, укр, eng)`) англійською
для English і українською для української й російської. Пуші приходять обома мовами, і телефон показує ту, якою читає
його браузер (`public/sw.js`). Статус-рядок `relay.sh` пише мовою локалі термінала.

Токени й ліміти. Хуки на `Stop`, `SubagentStop` і `SessionEnd` рахують токени з транскрипту (`plugin/scripts/relay.sh`):
вхід, запис і читання кешу, вихід. Кожне повідомлення асистента рахується один раз, субагент цілком, коли зупинився,
головний чат лише приріст з минулого разу (зсув у `~/.local/state/relay/usage/<сесія>`). Числа йдуть після рядка
`#relay-usage`, сервер бере їх лише з подій кінця ходу. `relay_hourly` тримає їх погодинно, по агентах, чатах і людях
(`supabase/migrations/0009_tokens.sql`). Ліміти 5 годин і тижня Claude Code віддає лише статус-рядку (`rate_limits`,
лише Pro/Max): `relay.sh statusline` зберігає їх у `~/.local/state/relay/limits`, а хуки на питанні, відповіді й кінці
субагента шлють останні після `#relay-limits`. З цих знімків кафе рахує прогноз (`forecast` у `lib/live/usage.ts`):
5-годинне вікно за темпом останньої години (поки Claude пів години мовчить, прогнозу нема), тиждень за середнім від
його початку. На шкалі блідий відрізок до того, де вікно буде на скиданні, червоний, якщо ліміт скінчиться раніше; у
підсумку те саме словами. Коли вікно, заповнене на 70% і більше або з «ліміт вичерпано», скидається при відкритому
кафе, `useLimitResets` показує зелену плашку «ліміт скинувся», дзвенить і шле сповіщення на робочий стіл. Чи запускає статус-рядок десктоп-застосунок, документація не каже. Тому є ще хук
`StopFailure`: коли хід обірвався на `rate_limit`, у шапці червоне «ліміт вичерпано», на залі «! ліміт», сповіщення й
пуш кажуть те саме, а в підсумку пояснення, що коли ліміт скинеться, Claude Code не повідомляє. Назва чату приходить і з
транскрипту (`#relay-title`), і просто з `session_title` у самому хуку, тож зали названі як чати навіть зі старими
хуками. `relay.sh` шле свою версію після `#relay-v`; якщо в останній твоїй події її нема, сторінка просить оновити
підключення тією самою фразою. На сайті: токени в шапці й у картці агента, стоси паперу на столах, табло «ток/хв» під
вивіскою, «Токени» й «Ліміти підписки» в підсумку, досягнення «Мільйон токенів» і «Мільярд токенів».

Кавник контексту. Замість чашки на столі стоїть скляний кавник, налитий настільки, наскільки зайнятий контекст агента.
`relay.sh` додає до `#relay-usage` вхід останньої відповіді (`ctx`) і розмір вікна (`win`, 200 тис. або 1 млн), якщо
статус-рядок його бачив (`~/.local/state/relay/ctx/<сесія>`). Без розміру сайт вважає вікно 200 тис., а понад 200 тис.
— 1 млн (`fillOf` у `lib/live/usage.ts`). Субагент починає з порожнього кавника й наливає його, коли закінчив.
Після стиснення (`SessionStart` з `source: "compact"`) кавник зливається до дна, а наступна відповідь показує точний
рівень. Від 80% верх кавника блимає, у картці агента «контекст N%». Потрібні хуки версії 3.

Ціна й контекст у картці агента. `relay.sh` 8 додає до `#relay-usage` модель останньої відповіді в транскрипті
(`"m":"claude-opus-5-5"`); сервер лишає лише `claude-[a-z0-9.-]`. Картка пише «контекст 42% · 84 тис. з 200 тис.,
лишилось ~116 тис.» і «витрати ≈ $1.44 · Opus 5.5 · 99% витрат чату»: скільки ці токени коштували б за цінами API
(`lib/live/price.ts`, запис у кеш за 1,25 ціни входу). «≥» замість «≈» значить, що частина токенів прийшла без моделі
(старі хуки) і не порахована. На підписці Pro чи Max це не гроші, а частка ліміту: дорожча модель з'їдає його швидше.
Підказка над токенами розкладає їх на вхід, запис і читання кешу та вихід.

Хто кого запустив. Під «хто кого запустив» у картці агента той, хто доручив йому задачу («↑ запустив bug-fixer», клік
відкриває його картку), і дерево субагентів, яких він запустив за останні 3 години, з тим, що кожен робить зараз. Рядків
до 8, решта «і ще N»; клік на рядок відкриває картку агента.

Застряг або ходить по колу (`lib/live/stuck.ts`, `lib/live/useStuck.ts`). Кафе раз на 15 с дивиться на кожен чат. По
колу: остання дія агента вже була, той самий крок з помилкою тричі серед останніх десяти дій або та сама команда,
пошук чи сторінка п'ять разів, і остання з них не старша за 15 хв. Затягнулось: від останнього `⏱` минуло більше, ніж
Claude оцінив, на 15 хв або на половину оцінки, якщо це більше, хід не закінчився, а чат не мовчить понад 20 хв. Тоді
на табличці агента чи в його бульбашці помаранчеве «! ходить по колу ×3», на дошці чатів «!» з тим, що повторюється, у
списку агентів «по колу» чи «затягнулось», а в картці пояснення. Нове попередження, поки кафе відкрите, дзвенить (дві
тривожні ноти двічі) і шле сповіщення, якщо вони ввімкнені. Рахується в браузері, тож пушу на закритий телефон нема.

Скільки лишилось (`lib/live/eta.ts`, `components/live/PipelineEta.tsx`). У смузі зверху, поряд з агентами й
токенами, стоїть «пайплайн ≈ 2 год 20 хв, о 18:40»: коли повернеться найдовший агент. Кнопка відкриває панель, де
кожен агент, що працює, має свій час, кроки й годину, коли закінчить, а ті, що вже повернулись, показують, скільки
працювали. Свій час агент має ще в списку агентів і в картці. Час приблизний. Якщо агент веде список задач (TodoWrite
або TaskCreate і TaskUpdate), час рахується з роботи, що лежить перед ним зараз: перевірка 20 екранів займе вчетверо
довше, ніж 5. Сервер бере з хука лише два числа, скільки кроків зроблено й скільки всього, без слів самих кроків. Час —
це кроки, що лишились, помножені на час одного кроку. Поки жоден крок не зроблено, час кроку береться з попередніх
завдань цього типу агента; з кожним зробленим кроком важить усе більше темп цього завдання. Агент без списку теж має
цифру, грубішу: скільки зазвичай тривають завдання цього типу, мінус те, що він уже працює (у картці «такі роботи
тривають ~2 год 30 хв»); якщо він працює вже довше, ніж зазвичай, йому дається ще чверть від того часу. Тип, чиє
завдання ще жодного разу не закінчилось, бере звичайне завдання будь-якого агента. Усе це медіани, у пам'яті браузера
`relay.runs`, останні 30 завдань кожного типу. Цифри немає, лише поки не закінчилось жодне завдання жодного агента; зі
списком, але без жодного темпу, видно тоді «кроки 0/20». Час Claude — це найдовший з агентів, на яких він чекає, або
його власний список, якщо той довший; агенти у фоні рахуються й після його відповіді. Коли хтось із агентів без
оцінки, у Claude «≥». Коли всі кроки списку зроблено, «майже».

Але агентів, яких Claude покличе потім, ці лічильники не бачать: пайплайн, що шле фіксерів, потім рев'ю, потім QA, а
потім знову фіксерів, на кожному кроці здається за кілька хвилин до кінця, хоча попереду ще години. Тому з хуками 7
Claude сам каже, скільки лишилось (`lib/live/checkin.ts`). Поки чат запускає субагентів, `relay.sh checkin` (синхронний
хук на `UserPromptSubmit` і `PostToolUse` інструмента Agent, працює лише з файлом у `~/.local/state/relay/checkin`, у
мережу не ходить) щонайбільше раз на 20 хвилин і лише тоді, коли Claude і так бере хід (питання, повернувся агент),
дає йому контекст, видимий лише йому: закінчи відповідь рядком `⏱ 95m · 6/10 · що зараз`, своєю чесною оцінкою до
кінця всієї роботи, з раундами, яких ще не почато. Рядок лишається в чаті, тож видно його й у Claude Code. Хуки
`PreToolUse` (поки відповідь на запит не прийшла) і `Stop` знаходять найновіший такий рядок у відповідях Claude в
транскрипті й шлють у кафе лише його, з часом, коли Claude його написав (`#relay-eta`). Час пайплайну рахується від
нього вниз; якщо якийсь агент явно потребує більше, береться його час. Коли час Claude минув, у смузі «довше, ніж казав», а
свіжа оцінка приходить з його наступним ходом. Оцінка старша за свій же час удвічі (щонайменше на годину) вже нічого не
важить, `⏱ 0m` означає «все». Інтервал змінює `RELAY_CHECKIN` у хвилинах, `RELAY_CHECKIN=0` вимикає запитання. HTTP-хуки
Windows без Git Bash цього не вміють. Кожен запит коштує Claude ~120 токенів на вході й ~25 на виході.

Сцена клікабельна (`components/cafe/hit.ts`): агент відкриває картку (що робить, скільки лишилось, останні 5 дій, час у
роботі, токени), кіт муркоче, дошка відкриває підсумок, автомат із напоями й мішечок зерен над стійкою кав'ярню,
музичний автомат свої платівки, вікно перемикає тему, двері запрошують команду. Агенти й журнал виїжджають шторками,
кнопка в шапці сцени розгортає її на весь екран.

Присутність і реакції (`lib/live/useSocial.ts`): у хмарному режимі кожна відкрита вкладка кафе відмічається в Realtime
presence на окремому каналі `relay-social:<кімната>`, не на каналі подій. Хто ще дивиться, видно в шапці сцени, а
перші троє сидять на барних стільцях (`components/cafe/guests.ts`). З картки агента можна кинути реакцію (👏 🔥 ☕ ❤️ 😂
🎉): вона летить broadcast-ом усім у кафе й спливає над його столом з іменем того, хто кинув. Нічого не зберігається;
чужі повідомлення проходять перевірку (`lib/live/social.ts`). Глядач за посиланням теж може кидати реакції. Локальний
Agent Lounge показує реакції лише в самій вкладці.

Ігри (кнопка з джойстиком у шапці сцени, `components/live/GamesPanel.tsx`), поки агенти працюють:

- «Ставки» (`lib/live/useBets.ts`): коли Claude доручає задачу субагенту, під сценою з'являється ставка, скільки той
  працюватиме: до 2 хв, 2–8 хв чи довше. Ставки приймаються 90 секунд, результат видно, щойно субагент зупинився.
- «Лови чашки» (`components/games/CatchCups.tsx`): 30 секунд бариста кидає чашки, тацю ведеш мишкою, пальцем або
  стрілками; золота чашка дає три.
- «Удвох» з кимось, хто теж зараз у кафе: запрошення спливає в нього плашкою (`lib/live/useDuels.ts`).
  Шахи (`lib/live/chess.ts`), шашки (`lib/live/checkers.ts`), аерохокей до 5 голів (`components/games/Hockey.tsx`),
  хрестики-нулики (`lib/live/useTicTacToe.ts`), пінг-понг до 5 очок (`components/games/Pong.tsx`) і «Кабелі» до 3
  виграних раундів (`components/games/Cables.tsx`). На дошках підсвічено останній хід суперника, а коли ігри закрито
  й партія чекає на твій хід, зверху з'являється плашка (`components/live/TurnToast.tsx`). Коли партія скінчилась,
  «ще раз» кличе того самого суперника в ту саму гру: він відповідає просто на дошці, а якщо закрив її, то в плашці
  запрошення. Звуки зроблено через Web Audio (`lib/live/sfx.ts`), вимикаються кнопкою біля повного екрана.
  Шахи й шашки можна грати на годиннику, як бліц: над кнопками ігор вибираєш 1, 2, 3, 5 чи 10 хвилин на кожного.
  Годинник іде лише тоді, коли твій хід, починаючи з першого ходу білих, і хто перший вичерпав час, той програв
  (`lib/live/clock.ts`, `lib/live/useTurns.ts`). Свій час кожен екран рахує сам і шле разом із ходом, тож затримка
  в дорозі ні на кого не лягає; якщо суперник зник, твій екран зараховує йому поразку за 3 секунди після нуля.

Ставки, запрошення й ходи хрестиків-нуликів, шашок і шахів летять тим самим каналом `relay-social:<кімната>`
(`lib/live/bus.ts`). Шашки грають за звичними правилами: бити обов'язково, назад теж і кількома стрибками, дамка
ходить на будь-яку відстань. Кожен хід летить разом з усією партією й повторюється, поки суперник не відповів, тож
загублене повідомлення нічого не ламає (`lib/live/useCheckers.ts`). Шахи — за повними правилами: рокіровка, взяття
на проході, пішак стає фігурою на вибір, мат і пат, нічия за 50 ходами без взяття, третім повтором позиції чи коли
нічим поставити мат; ходи летять так само, як у шашках (`lib/live/useChess.ts`).
Пінг-понг відкриває свій канал на партію, `relay-pong:<кімната>:<гра>`, щоб решта кафе не отримувала кожен рух ракетки.
Кожен гравець вирішує, чи відбив він м'яч своєю ракеткою, і каже про це іншому. Між цими повідомленнями обидва ведуть
той самий м'яч, а отримане зсувають на половину виміряного часу туди й назад (`lib/live/pong.ts`).
«Кабелі» йдуть кроками по 100 мс на своєму каналі `relay-cables:<кімната>:<гра>`: поворот діє через три кроки після
натискання, а крок робиться, лише коли відомі повороти обох. Тож обидва екрани рахують ту саму гру й ту саму аварію
без суперечок (`lib/live/cables.ts`). Аерохокей на каналі `relay-hockey:<кімната>:<гра>`: шайбу рахує той, на чиїй
половині вона зараз, разом з ударом його бити й голом у його ворота, і шле її 20 разів на секунду. Коли шайба
перетинає червону лінію, вона переходить до суперника, а бита не заходить так далеко, щоб дістати шайбу на чужій
половині. Тож кожну биту судить екран її гравця (`lib/live/hockey.ts`). У базу пишеться лише рахунок:
`relay_scores` через `relay_score_add` (лише з ключем, не частіше разу на 2 с на гравця й гру, до 300 рядків на
кімнату, `supabase/migrations/0010_games.sql`). За посиланням для перегляду грати можна, але рахунок не пишеться.
Локально рахунок лежить у `localStorage`, а ігри удвох потребують хмарного режиму.

Інтер'єр і кавові зерна. Робота Claude приносить кафе зерна (`lib/live/interior.ts`): питання 3, доручення 5,
відповідь 1, хвилина в роботі 1, кожні 4 дії ще одна, досягнення 30, а перше питання кожного дня ще 100 (дні
беруться з тих самих денних підсумків, що й для досягнень). 13 жовтня 2026 рахунок у всіх кафе почався
заново (`BEANS_FROM`): зерна дає лише робота після цієї години, сумована з `relay_hourly` через `relay_beans`
(`supabase/migrations/0013_beans.sql`), і досягнення, отримані після цього дня. Платять лише за речі, куплені відтоді
(`interior.paid`); куплене раніше лишилось у кафе. Скільки зерен лишилось, видно на сумці в шапці й на мішечку над
стійкою. Над мішечком спливає, що щойно принесла робота: «+2 ☕ доручення агенту», «+20 ☕ перше питання дня»
(`lib/live/useBeanGains.ts`). За зерна в кав'ярні (сумка, мішечок або автомат із напоями в сцені) купуються 17 речей: свічка,
кактус, кіт-манекі й бонсай на підвіконня; три постери на стіну; килимок; на підлогу лежак для кота, торшер, пальма,
книжкова шафа, грамофон, диван і музичний автомат (`components/cafe/furniture.ts`). Ще дві речі одна на кафе: неонова
вивіска, на якій можна написати свій другий рядок замість «інтернет-кафе», і другий кіт, сірий, зі своїм ім'ям.
Окремо, під золотою рамкою, чотири рідкісні речі, теж по одній на кафе, кожна на кілька днів роботи: золотий кіт-манекі
(1 500), диско-куля (2 000), піаніно (3 000) і камін (4 500), що світить у залі (`components/cafe/rare.ts`). Куплену
річ ставиш клацанням на сцені: зелена рамка означає, що місце вільне, червона, що ні. Поставлену можна перетягнути
мишею або клацнути й вибрати «перемістити» чи «прибрати». Зароблений декор (аркадний автомат, акваріум, рослина в
кутку, сова) рухається так само, а «на звичне місце» повертає його туди, де він стояв. Столи в кожному чаті стоять
по-своєму, тож річ, якій заважає стіл, відступає на найближче вільне місце (`components/cafe/placement.ts`). У картці
агента можна змінити, хто він (людина, робот, кіт чи прибулець), зачіску, колір волосся, шкіри, металу чи шерсті й
одягу, річ на столі (кактус, качка, банки, книжки, лампа або нічого) і дати табличку з ім'ям. Ім'я заміняє його назву
над столом, у бульбашці, в картці, у списку агентів і в панелі часу. Те саме для всіх агентів чату одразу є у вікні
«кав'ярня», розділ «Агенти», з маленьким персонажем поруч. Ім'я й вигляд тримаються типу агента (`@bug-fixer`,
`lookKey` у `lib/live/interior.ts`), тож bug-fixer однаковий за будь-яким столом і в кожному чаті, а другий, що
працює одночасно, вдягнений так само й зветься «Ім'я 2». До 0.13 вигляд тримався номера столу (`seat-3`); такий
лишається, доки агента вперше не переодягнуть, тоді переїжджає до нього. Пак персонажів міняє лише вбрання: хто агент,
його шкіра й ім'я лишаються. Одяг за столом видно лише краєм, повністю тоді, коли агент ходить. Усе це лежить у
`relay_rooms.interior` (`supabase/migrations/0011_interior.sql`), тож глядач за посиланням бачить те саме кафе.
Локально інтер'єр лежить у `localStorage`.

Теми: нічне кафе (дощ і місто), космічна станція (панелі, планета в ілюмінаторах, зорі пливуть), лісовий табір
(колоди, ялини, світлячки) і зимовий вечір (сніг на дахах і за вікном). Палітри лежать у `components/cafe/theme.ts`,
вікна й погода в `components/cafe/windows.ts`. Тему обирають у вікні «кафе»; вона зберігається в `relay_rooms.theme`
поруч з ім'ям кота, тож глядач за посиланням бачить ту саму. Локально тема лежить у `localStorage`.

Плагін Claude Code (`plugin/`) ставить ті самі хуки, але `settings.json` не чіпає: посилання на кафе лежить у
`~/.config/relay/hook-url` (права 600). Його записує `/agent-lounge:connect <посилання>`, а `/agent-lounge:status` показує, куди
йдуть події. Без посилання хук мовчки нічого не шле. Сайт сам роздає маркетплейс: `/plugin marketplace add
<сайт>/marketplace.json` (`app/marketplace.json/route.ts` віддає архів `public/agent-lounge-plugin.zip` з sha256; потрібен
Claude Code 2.1.224 або новіший). Після змін у `plugin/` перепакуй: `npm run plugin:pack` (той самий вміст дає той
самий sha256). Локально плагін береться прямо з репозиторію: `claude plugin marketplace add ~/agent-lounge`,
`claude plugin install agent-lounge@agent-lounge`, а в чаті `/agent-lounge:connect local`. Вимкнути: `/plugin disable agent-lounge`.

Потрібні ще три змінні: `NEXT_PUBLIC_VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`
(ключі: `npx web-push generate-vapid-keys`). Без них сайт працює, просто без пушів.

### Локально (нічого не йде в мережу)

Для власника репозиторію: інструкція для Claude лежить у [`public/setup.md`](../public/setup.md). Руками:

```bash
git clone https://github.com/justbios/agent-lounge.git ~/agent-lounge
cd ~/agent-lounge
npm install
npm run setup         # хук у ~/.claude/settings.json + Agent Lounge у фоні на http://127.0.0.1:3737
```

| Команда | Що робить |
|---|---|
| `npm run setup` | `hooks` + `up` |
| `npm run hooks` / `npm run unhook` | додає / прибирає хук у `~/.claude/settings.json` (або `$CLAUDE_CONFIG_DIR`) і кладе скрипт у `~/.config/relay/relay.sh`. Решту налаштувань не чіпає, бекап `settings.json.bak-relay`, повторний запуск нічого не міняє. `node scripts/install-hooks.mjs --statusline` додає статус-рядок для лімітів, наявний лишає зі своїм виводом |
| `npm run up` / `npm run down` | збирає й тримає Agent Lounge у фоні (лог `data/server.log`) / зупиняє. `npm run up -- --restart` після `git pull` |
| `npm run live` | те саме на передньому плані, в терміналі |

Сторінка сама обирає режим: на `127.0.0.1` / `localhost` вона читає локальний Agent Lounge, на будь-якому іншому домені
хмарну кімнату. Хуки обох режимів живуть у `lib/live/hookConfig.mjs`. Вони асинхронні (`async: true`), мовчазні й
завжди виходять з 0: не гальмують агентів, не витрачають токенів, а коли адресат недоступний, curl тихо падає.

Події тримаються в пам'яті процесу Agent Lounge (і в `data/live-events.jsonl`, щоб пережити перезапуск) і нікуди з машини не йдуть. Перевірити без
справжнього Claude можна так: `node scripts/simulate-claude.mjs` програє вигадану сесію.

```
Claude Code hooks ──curl──▶ /api/claude-hook ──▶ lib/live/store (пам'ять)
                                                        │ SSE /api/live
                                                        ▼
                         useLiveFeed → buildLiveModel → CafeScene
```

## Демо локально

Потрібен **Node ≥ 18** (розроблялось на Node 20). На зовнішньому SSD dev-сервер
запускай з `--webpack`: Turbopack спотикається об macOS-файли `._*`.

```bash
npm install
npm run dev -- --webpack
# http://localhost:3000
```

## Як воно влаштоване

```
Claude Code хуки ──▶ relay.sh ──▶ /api/claude-hook ──▶ relay_ingest (Supabase) ──realtime──▶ кафе в браузері
                                  (або локально: in-memory store + SSE на 127.0.0.1:3737)
```

Хуки шлють JSON події як є; сайт нормалізує його в `LiveEvent` і малює кафе. Демо-режим програє
змодельований прогін і нікуди не ходить.
